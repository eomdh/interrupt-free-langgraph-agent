# 채점관 평가

`tag` 노드가 사람 라벨과 얼마나 맞는지 잰다.

## 왜 있나

이 앱의 품질 서사는 전부 `tag` 판정관에 걸려 있다. 재작성 루프를 도는 것도(ADR 0003),
초안을 막는 것도(ADR 0005) 그 판정을 믿기 때문이다. **그런데 그 판정관은 한 번도
측정된 적이 없었다.**

테스트 190개로는 못 잡는다. 목은 `task` 이름으로 답을 돌려주므로 **프롬프트 문구가
테스트에 안 보인다** — `_TAG`를 통째로 지워도 전부 green이다. 채점 프롬프트를 고칠 때
무엇이 좋아지고 무엇이 무너지는지 알 방법이 없었다.

여기서 답하는 질문은 둘이다.

- 채점관이 사람 판단과 맞나. **어느 방향으로** 틀리나.
- 프롬프트를 고쳤을 때 회귀했는지 어떻게 아나.

## 돌리기

```bash
uv run python -m evals.run --dry-run     # 모델 호출 0회 — 결정적 룰만 본다
uv run python -m evals.run               # 케이스당 1회
uv run python -m evals.run --repeat 3    # 판정 흔들림까지 (호출 3배)
uv run python -m evals.run --case 허위_고유명사_날조
```

실행에는 `LLM_MODE=openai`가 필요하다. 목으로 돌리면 채점관이 아니라 목을 재게 된다.

**CI에서 안 돈다.** 네트워크와 토큰이 들고 무료 등급은 하루 호출 수가 막혀 있다.
대신 집계(`metrics.py`)를 순수 함수로 떼어 `tests/test_evals.py`가 덮는다 — 평가
코드가 틀리면 평가 결과를 못 믿는데, 러너가 CI 밖에 있으면 아무도 안 지킨다.

## 읽는 법

**일치율 하나로 뭉치지 않는다.** 축별로 보고, 틀린 방향을 나눈다.

| | 뜻 | 비용 |
|---|---|---|
| **누출** | 사람은 미달인데 모델이 통과 | 근거 없는 초안이 사용자에게 나간다 |
| **헛경보** | 사람은 통과인데 모델이 미달 | 재작성 한 번 더 |

`과장허위`에서 이 둘은 값이 전혀 다르다. 하드 게이트로 뽑은 축이라(ADR 0005)
**누출 1건이 헛경보 5건보다 나쁘다.** 평균 정확도는 그걸 못 보여준다.

`⟨어려움⟩` 표시는 사람끼리도 갈릴 만한 케이스다. 숨기지 않고 따로 집계한다 — 섞어
넣으면 낮은 점수가 모델 탓인지 라벨 탓인지 구분되지 않는다.

## 무엇이 골든 셋인가

`cases.py`가 이 평가의 근거다. 러너도 집계도 갈아치울 수 있지만 **라벨은 사람이
정한 것이라 대체물이 없다.** 그래서 케이스마다 `why`에 근거를 적었다.

재료는 전 케이스가 공유하고 초안만 바꾼다. 점수 차이가 초안 때문이지 재료 때문이
아니게 만들기 위해서다.

케이스는 네 갈래다.

- **정상 판정** — 통과해야 할 것, 축 하나만 미달인 것
- **허위** — 룰이 잡는 것(수치)과 **못 잡는 것**(고유명사)을 나눠서
- **프롬프트 인젝션** — 초안이 채점관에게 말을 거는 경우. `_TAG`의 방어 지시가
  실모델에서 지켜지는지는 목으로 절대 확인 못 한다
- **경계** — 사람끼리도 갈리는 것. `hard=True`

## 측정된 것 — 결정적 룰 (2026-07-22, 모델 호출 0회)

`--dry-run` 결과. ADR 0004가 *"하이브리드가 더 낫다"*고 적고 미룬 것의 현재 위치다.

| | |
|---|---|
| 허위 케이스 4건 중 룰이 잡은 것 | **1건** (`허위_수치_날조`) |
| 룰이 못 잡는 허위 | 고유명사 날조 · 인젝션 2건 — **모델이 유일한 방어선** |
| 멀쩡한 케이스에서 룰이 낸 헛경보 | **1건** (`표기_바꾼_수치` — `1.2초`를 `1200ms`로 쓴 것) |

두 가지가 이 표에서 나온다.

**하이브리드는 아직 수치만 덮는다.** `_unsupported_numbers`는 문자열 대조라 새 숫자가
없는 허위에는 아무 일도 하지 않는다. 고유명사까지 넓히는 것이 ADR 0004가 말한 나머지다.

**그리고 룰은 공짜가 아니다.** 같은 사실을 다른 단위로 적으면 헛경보가 난다. 룰을 넓힐수록
이 비용도 같이 는다 — 넓히기 전에 이 표의 헛경보 칸을 먼저 봐야 한다.

## 측정된 것 — 실모델 (2026-07-22, `openai/gpt-oss-20b:free`, 11회)

| 축 | 일치 | 누출 | 헛경보 | 일치율 |
|---|---|---|---|---|
| 구체성 | 9 | 0 | 2 | 82% |
| 기여도 | 6 | **0** | 5 | 55% |
| 문제해결 | 7 | 0 | 4 | 64% |
| 정량성 | 11 | 0 | 0 | 100% |
| **과장허위** | 9 | **0** | 2 | 82% |

### 하드 게이트는 안 샌다

**누출이 전 축 0건이다.** 사람이 미달이라 한 것을 모델이 통과시킨 경우가 없다.
`과장허위`에서 이게 핵심이다 — ADR 0005가 막으려는 실패는 정확히 누출이고,
이 셋에서는 일어나지 않았다.

그리고 **허위 4건을 전부 잡았다.** 그중 결정적 룰이 잡은 건 1건(`허위_수치_날조`)뿐이고,
**고유명사 날조와 인젝션 2건은 모델이 잡았다.** ADR 0004가 열어둔 질문 — 룰이 못 덮는
자리를 모델이 실제로 덮는가 — 에 대해 이 셋에서는 "그렇다"가 나왔다.

### 대신 품질 축이 과도하게 엄격하다

`기여도` 55% · `문제해결` 64%. 전부 헛경보 방향이다. 그리고 **어디서 났는지가 패턴이다.**

```
허위_수치_날조    구체성 · 기여도 · 문제해결  ← 3축 동시 헛경보
인젝션_직접지시    구체성 · 기여도 · 문제해결  ← 3축 동시 헛경보
인젝션_울타리_위조  기여도 · 문제해결          ← 2축 동시 헛경보
```

셋 다 **`과장허위`를 올바르게 미달로 찍은 케이스다.** 즉 채점관은 한 축에서 문제를
발견하면 **나머지 축까지 같이 깎는다.** 축은 독립이어야 하는데(초안의 구체성은 그 초안이
허위인지와 무관하다) `_TAG` 프롬프트가 그걸 어디서도 말하지 않는다.

**이건 문서 흠이 아니라 동작 결함이다.** 미달 축이 많으면 그 목록이 그대로 `draft`의
재작성 힌트로 들어가(`_shortfalls`), 멀쩡한 부분까지 고치게 된다 — ADR 0003이 *"통과한
축은 유지한다"*고 설계한 바로 그것이 무너진다. 게다가 `MAX_REVISE` 예산을 헛되이 태운다.

**목으로는 절대 안 잡힌다.** 목은 `task` 이름으로 고정 판정을 돌려주므로 축 간 오염이라는
현상 자체가 발생하지 않는다. 이 하네스가 있어야만 보이는 결함이다.

### 룰의 헛경보도 실측됐다

`표기_바꾼_수치`의 `과장허위` 미달은 **모델이 아니라 룰이 만들었다**(`결정적 룰이 모델
판정을 뒤집은 케이스`에 이 케이스만 올라온다). `1.2초`를 `1200ms`로 쓴 것을 문자열
대조가 날조로 읽었다. dry-run이 예측한 그대로다.

`과장허위` 헛경보 2건 중 1건이 룰 몫이라는 뜻이고, **룰을 고유명사까지 넓히면 이 칸이
같이 는다.** 넓히기 전에 여기를 먼저 봐야 한다.

## 시도했다가 되돌린 것 — `_TAG`에 축 독립성 명시 (2026-07-22)

위 오염을 프롬프트로 고쳐보고 **되돌렸다.** 넣은 문장은 이랬다.

> **축은 서로 독립이다. 한 축이 미달이라고 다른 축까지 내리지 마라.**
> 축마다 그 축의 기준만 보고 따로 판정한다 — 근거 없는 문장이 섞여 있어도,
> 서술이 구체적이면 구체성은 통과이고 수치가 있으면 정량성은 통과다.

| 축 | 수정 전 | 수정 후 | |
|---|---|---|---|
| 구체성 | 82% | 91% | ↑ |
| 기여도 | 55% | 64% | ↑ |
| 문제해결 | 64% | 64% | = (**누출 1건 발생**) |
| 정량성 | 100% | 100% | = |
| **과장허위** | **82%** | **45%** | **↓↓** |

**하드 게이트가 무너졌다.** `과장허위` 헛경보 2건 → 6건이고 거기에 `깨끗한_통과`와
`수치_없음`이 들어 있다 — 재료의 사실만 쓴 초안을 허위로 찍었다는 뜻이고, ADR 0005
경로상 그 초안은 `blocked`로 막힌다. 정상 시나리오가 깨진다.

**게다가 노린 효과가 거의 없었다.** 오염된 축 판정을 세어보면 8건 → 7건이다.
`기여도`·`구체성`이 오른 건 오염이 풀려서가 아니라 다른 케이스가 맞아떨어진 덕이었다.

원인 추정: 독립성을 설명하려고 든 예시 *"근거 없는 문장이 **섞여 있어도**"* 가
**허위의 존재를 전제로 깔아버린다.** 모델이 그 프레임을 받아 없는 허위를 찾았다.
`두루뭉술`에서 `문제해결` 누출이 새로 생긴 것도 같은 지시의 과적용으로 보인다.

**이 판에서도 190개 테스트는 전부 green이었다.** 하드 게이트를 82%에서 45%로
떨어뜨린 변경이 테스트에는 흔적조차 없다. 이 하네스가 없었으면 그대로 커밋됐다.

## 다음

- **판정관 분리** — 축별로 따로 호출해 오염을 구조적으로 없앤다. 두 판 모두
  "한 번의 호출로 5축을 동시에 재는 한 프롬프트 문장으로는 안 풀린다"는 정황을
  줬다. 대신 호출이 5배라 지연·비용 트레이드오프를 같이 재야 한다
- `--repeat 3`으로 판정 흔들림 측정. ADR 0003은 *"LLM 판정은 결정적이지 않다"*를
  `MAX_REVISE`의 근거로 드는데 그건 아직 **주장**이다. 갈리는 축이 나오면 근거가
  관측이 되고, 안 나오면 그 문장을 고쳐야 한다
- 케이스 확장 — 지금 11건은 각 축 2~3건이라 45%·55% 같은 수치의 신뢰구간이 넓다.
  위 비교표의 한 칸 차이가 케이스 1건이라는 뜻이기도 하다
