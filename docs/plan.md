# 작업 계획

> **이 문서는 버리는 문서다.** 범위와 마일스톤을 잡아두는 용도이고, 구현이 끝나면 README가 대신한다.
> 설계 결정은 여기 쓰지 않는다 — `docs/adr/`에 한 건씩 남긴다. **이 문서와 코드가 어긋나면 코드가 맞다.**

## 무엇을 만드나

대화형 **성과 리뷰 초안 코치**. 평가 기간에 한 일을 인터뷰해서 성과 리뷰(자기평가) 초안을 만들어준다.
LangGraph `StateGraph`로 짜되, **`interrupt()` 없이** 매 POST를 한 번의 실행으로 처리한다.

한 줄 정체: *"`interrupt()` 없이 짠 자율 대화 에이전트 — 매 POST=1턴, 질문은 `AIMessage`로."*

## 왜 이 소재인가

에이전트가 사람에게 **되묻고 기다려야** 하는 구조라서, "사람 입력을 어떻게 기다릴 것인가"가 정면 문제로 드러난다. 그게 이 repo의 헤드라인(ADR 0001)이다. 단발 질의응답 챗봇으로는 그 문제가 안 생긴다.

## 범위 (MVP)

돌아가는 것이 1순위다. 아래가 전부 되면 멈춘다.

- [x] `StateGraph` — 매 POST = `ainvoke` 1회. 질문은 `AIMessage`로 남기고 END (ADR 0001)
- [x] `router` 허브 — intent × 상태 게이트로 목적지 노드 결정
- [x] 동의 게이트 — 초안 생성·확정 둘 다 사용자 승인 뒤에 (ADR 0002)
- [x] `draft ⇄ tag` self-eval 루프 — 5축 LLM 채점 + 미달 축만 힌트 재주입 + `MAX_REVISE=2` (ADR 0003)
- [x] 과장·허위 하드 게이트 — 입력에 없는 사실은 무조건 재작성 (ADR 0004)
- [x] Postgres 체크포인터 — 새로고침하면 문답 전체 복원
- [x] SSE 노드 진행 스트림 → React 스텝퍼 + 우측 산출물 패널
- [x] LLM 목 모드 — 키 없이 `docker compose up` 하나로 데모가 돈다

## 안 하는 것

repo 관리 규약 §8.2 — *"안 돌아가는 repo는 repo 없는 것보다 나쁘다."* 아래는 시그널을 희석시켜서 뺀다.

- 인증·회원가입 (스레드 ID만으로 충분)
- 배포 인프라 (compose까지만)
- 진짜 토큰 스트리밍 — 노드 단위 progress까지만. 여력 남으면 고도화
- 라우터 intent **임베딩** 분류 — few-shot 분류로 시작했다(ADR 0008). 임베딩까진 안 간다
- 체크포인터 마이그레이션 전략

## 마일스톤

각 단계가 **끝날 때마다 돌아가는 상태**를 유지한다. 큰 덩어리 커밋 금지.

| # | 목표 | 완료 기준 | |
|---|---|---|---|
| 1 | 그래프 뼈대 + 라우터·게이트·self-eval 판단 | 전이·상한·fail-safe가 테스트로 고정된다 | ✅ |
| 2 | 워커 노드 + LLM 경계 | 목으로 온보딩→확정이 한 번에 돈다 | ✅ |
| 3 | FastAPI 1턴 + Postgres | 앱을 재시작해도 대화가 남는다 | ✅ |
| 4 | 실제 LLM 클라이언트 | OpenAI 호환 엔드포인트로 진짜 응답이 온다 | ✅ |
| 5 | SSE 진행 스트림 | 노드 전환이 실시간으로 흘러나온다 | ✅ |
| 6 | 프론트 스텝퍼 + 산출물 패널 | 자율 루프가 "도는 중"으로 보인다 | ✅ |

> 3·4번은 원래 계획에서 각각 "동의 게이트"·"self-eval 루프"였다. 그 둘의 **판단 로직은 1번에서 이미 끝나서**, 남은 노드 구현과 HTTP 계층으로 표를 다시 잡았다.

## 실제 모델 검증 (2026-07-22 · `openai/gpt-oss-20b:free`)

개발·테스트는 `LLM_MODE=fake`로 한다 — 무제한이고 결정적이라 그쪽이 낫다.
**다만 프롬프트 품질은 목으로 절대 안 잡힌다.** 목은 `task` 이름으로 답을 돌려주므로
프롬프트 문구를 아무리 바꿔도 테스트는 green이다. 아래는 실제 모델로 확인했다.

- [x] 초안에 규칙 준수 보고·자기 평가가 안 섞인다 — 붙여넣을 본문만 나온다
- [x] STAR 소제목 없이 산문으로 나온다
- [x] 재작성 루프가 상한 전에 통과한다 — 재료가 온전하면 **첫 초안에 5축 전부 통과**(`revise_count=0`)
- [x] `interview`·`respond`가 자연스러운 한국어를 낸다 — **단, `interview`는 고치고 나서다**

`interview`가 *"귀하가 직접 수행한 … 명시해 주시겠습니까?"* 같은 관공서체를 냈다.
문법은 맞지만 앱의 다른 문구("편하게 말씀해주세요")와 톤이 어긋나서, 프롬프트에
말투 지시를 넣었다. 지금은 *"… 어떻게 측정되었나요?"* 로 나온다.

**목이 못 잡는 결함이 실제로 있었다는 뜻이고, 이 절이 존재하는 이유다.** 프롬프트
문구는 테스트가 못 지키므로, 고칠 때마다 여기로 돌아와 실제 모델로 다시 봐야 한다.

무료 모델은 업스트림 429가 잦다. 한 판에 4~8회를 쓰므로 모아서 돌리는 편이 낫다.

## 테스트 (원본 0건 → 여기서 정공법)

날카로운 것 몇 개 > 커버리지.

- 라우터: intent × 게이트 조합별 목적지 노드
- 카운터 리셋: `operator.add` reducer가 값을 못 줄이는 함정의 회귀
- 동의 게이트 전이: 승인 없이는 `draft`로 못 간다
- self-eval 루프가 `MAX_REVISE`에서 멈춘다
- fail-safe: 누락·불량 라벨이 전부 미달로 정규화된다
- 과장·허위 게이트: 입력에 없는 고유명사가 통과하지 못한다

LLM은 결정적 스텁으로 목킹, 체크포인터는 `MemorySaver`.

**목이 못 덮는 것**: 프롬프트 문구, 모델의 JSON 준수, 한국어 품질. 위 "실제 모델 검증 대기" 참조.
