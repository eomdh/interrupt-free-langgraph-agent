# ADR 0003 — 초안도 LLM, 채점도 LLM: self-eval 루프와 재작성 상한

- **상태**: 채택
- **관련**: ADR 0004

## 맥락

성과 리뷰 초안은 한 번에 좋게 나오지 않는다. 구체성이 부족하거나, 본인 기여가 안 드러나거나, 숫자가 빠져 있다.

사용자에게 매번 "이 부분 고쳐줘"를 시키면 대화가 지친다. 리뷰를 쓰러 온 사람이 초안 품질 관리까지 하게 되는 건 도구의 실패다.

## 결정

**초안 생성과 채점을 그래프 안에서 자율로 돌린다.** `draft`가 쓰고 `tag`가 채점하고, 미달이면 다시 `draft`로 돌아간다.

5축으로 채점한다 — **구체성 · 기여도 · 문제 해결 · 정량성 · 과장 허위.**

세 가지를 함께 건다:

**1. 통과 축은 유지하고 미달 축만 힌트로 재주입한다.** 전체를 다시 쓰면 통과했던 축이 무너진다. `tag`가 미달로 찍은 축에 대해서만 개선 힌트를 만들어 `draft`에 넘긴다.

**2. `MAX_REVISE = 2`.** 무한 루프를 막는 상한. 도달하면 미달인 채로 사용자에게 내보내고, **무엇이 부족한지 같이 알려준다.** 조용히 통과시키지 않는다.

**3. temperature를 분리한다.** 판정 `0` / 생성 `0.4`. 채점은 같은 입력에 같은 답이 나와야 하고, 생성은 어휘 다양성이 필요하다.

## 근거

**루프를 도는 게 보이면 기다릴 수 있다.** 자율 루프의 진짜 비용은 시간이 아니라 **불투명함**이다. 30초 동안 아무것도 안 변하면 사용자는 멈춘 걸로 읽는다. 재작성 중이라는 걸 "한 번 더 다듬을게요"로 노출하면 같은 30초가 견딜 만해진다.

**상한이 없으면 품질 기준이 곧 무한 루프다.** 채점이 엄격할수록 통과가 어려워지는데, LLM 판정은 결정적이지 않아서 같은 초안이 돌 때마다 다르게 찍힐 수 있다. 상한이 유일한 종료 보장이다.

**미달인 채 내보내는 게 정직하다.** 상한에서 억지로 통과시키면 사용자는 완성됐다고 믿는다. "구체성이 아직 부족합니다"를 붙여 내보내는 쪽이 신뢰를 지킨다.

## 대안

**사용자가 매번 지시** — 통제권은 확실하나 피로하다. 애초에 이 도구를 쓸 이유가 줄어든다.

**단발 생성, 채점 없음** — 단순하고 빠르다. 품질 편차를 전부 사용자가 떠안는다.

**규칙 기반 채점** — 결정적이라 매력적이지만, "기여도"나 "문제 해결"은 규칙으로 못 잰다. 다만 **과장·허위 축만은 규칙이 더 낫다** → ADR 0004에서 분리.

**같은 모델이 쓰고 채점하는 것 자체를 피한다 (판정관 분리)** — 더 나은 방향이라고 본다. 생성자와 다른 모델이 채점하면 자기 출력에 관대한 편향이 줄어든다. **MVP에서는 안 한다** (모델 하나로 시작). 고도화 후보.

## 결과

**얻는 것** — 사용자가 품질 관리를 안 해도 된다. 5축 채점이 산출물 패널에 그대로 노출돼서 **에이전트가 자기 출력을 어떻게 보는지가 화면에 드러난다.**

**감수하는 것** — **자기 채점의 정확도를 검증한 적이 없다.** 모델이 "구체성 통과"라고 찍은 게 실제로 구체적인지 잰 적이 없다는 뜻이다. 소량이라도 사람이 라벨링한 셋으로 축별 정확도를, 특히 과장·허위 축의 재현율을 따로 재야 한다. 지금은 안 되어 있다.

같은 모델이 쓰고 채점하므로 **자기 출력에 관대할 수 있다.** 판정관 분리 전까지는 남는 한계다.

응답이 느려진다. 재작성 1회당 LLM 호출이 2회(생성+채점) 더 붙는다. 진행 스트림이 이걸 견디게 해주는 장치다.
